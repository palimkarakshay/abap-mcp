# TRL run, 2026-09-29: the safe-agent demo on a real SAP BTP ABAP Environment

The offline harness (`run.mjs`) says the planted bugs in tasks 05 and 06 are invisible to lint and
readiness, and only an executed ABAP Unit test catches them. This run repeats those tests on a real
ABAP Cloud system instead of the offline open-abap kernel. It also sends task 03's classic report to
the same system to see what ABAP Cloud does with it.

**Result: the trial reproduced the offline harness exactly.** Both solutions pass. Each baseline fails
the one test that targets its planted bug, with the same numbers the harness predicts. The classic
report was not imported: the ABAP environment does not support object type PROG.

All code is synthetic ("Northwind Bikes"). The objects were renamed into the owner's trial namespace
`ZLV_`. No client or employer code was used.

## How to reproduce

You need a dev-scoped token in `~/.abapd-token.json`: run `node ~/projects/lumivara-fifa/sap/tools/refresh-token.mjs`,
or `passcode-login.mjs` first. You also need the service key at `~/.zlv-fifa-abap.json`. The scripts import the
existing connection seam (`lumivara-fifa/sap/tools/{conn,adt}.mjs`, which resolves `abap-adt-api` from
`lumivara-fifa/sap/node_modules`) and the guardrails by absolute path. abap-mcp gets no new npm deps.

```bash
cd demo/safe-agent/trl
node build-abapgit-repo.mjs                 # 4 classes -> ~/projects/nwb-safe-agent-demo (BOM on .xml, escaped descriptions)
#   git init/commit; gh repo create palimkarakshay/nwb-safe-agent-demo --public --source . --push
node deploy.mjs package                     # registerPackage + create ZLV_NWBDEMO (ZLOCAL) via create-package.mjs
node deploy.mjs link                        # gitCreateRepo
node deploy.mjs pull 1                      # gitPullRepo, poll every 60 s, save raw/pull-1-{repo.json,log.xml}
node deploy.mjs activate                    # activate inactive ZLV_NWB* objects
node run-unit.mjs                           # ABAP Unit on TRL -> raw/aunit-*.xml + raw/aunit-summary.json
node build-abapgit-repo.mjs --with-prog     # add task 03 PROG; commit + push as a separate commit
node deploy.mjs pull 2 && node deploy.mjs activate && node run-unit.mjs
node deploy.mjs status                      # read-only: repo entry + which objects exist
```

## Notes and deviations

- The old bridge helpers `abapd-trainer/bridge/git-{link,pull-wait}.mjs` no longer run: they resolve
  `abap-adt-api` from `abap-enclave-mcp` (not installed) and read the removed code-server profile.
  `deploy.mjs` reimplements their link, pull and poll logic on top of `conn.mjs`.
- Re-pulling puts the imported classes back into the inactive state. Run `deploy.mjs activate`
  after every pull, before `run-unit.mjs`.
- `raw/aunit-summary-after-pull1.json` holds the first unit run. `raw/aunit-*.xml` and
  `raw/aunit-summary.json` hold the second run. The results are identical.
- The owner email in the abapGit repo entries (`raw/pull-*-repo.json`) was redacted.
- `registerPackage` rewrites the registry note in `abapd-trainer/OWNED-PACKAGES.json`. The history
  note was restored by hand, with a 2026-09-29 line added for `ZLV_NWBDEMO` (4 of 8 package slots used).
